# Brand X Intelligence Radar 产品白皮书

版本：MVP 0.1  
文档属性：公开脱敏版  
适用范围：品牌公开舆情监测、每日情报归档、管理层与业务团队评审

## 1. 摘要

Brand X Intelligence Radar 是一个面向品牌团队、市场团队、公关团队和管理层的品牌公开舆情情报产品。它将公开社媒中的分散讨论转化为中文优先、证据可追溯、优先级可解释的舆情仪表盘，帮助团队回答三个日常问题：

1. 今天哪些舆情最值得优先看？
2. 每条舆情为什么重要，证据来自哪里？
3. 主品牌相对于样例竞品的公开讨论热度和风险语境有什么变化？

当前 MVP 聚焦“日常发现、快速判断、证据复盘、日报归档”四个核心能力。产品不是营销看板，也不是单纯的社媒列表，而是把公开内容、传播指标、品牌相关度、风险/机会判断和建议动作组织成一套可复盘的情报工作流。

## 2. 背景与问题

品牌在公开社媒中的讨论呈现出典型的“高噪声、弱结构、跨语言、扩散快”的特征。业务团队往往面对以下痛点：

- 内容分散：用户投诉、正向体验、竞品对照、渠道信息和行业背景混在一起，人工浏览成本高。
- 语言割裂：非中文内容需要先翻译再判断，影响晨会、日报和跨团队同步效率。
- 误匹配多：品牌简称、别名和上下文含义容易混淆，直接关键词抓取会把噪声带入汇报。
- 优先级不清：高互动不一定高风险，低互动也可能具备业务敏感性，团队需要一套稳定的判断框架。
- 证据链薄弱：结论如果不能回到原帖、作者、互动指标和相似讨论，很难支持公关、客服、运营或管理层动作。
- 历史不可复盘：每天的舆情如果只是临时截图或群内消息，后续难以对比趋势、追踪问题重复出现和沉淀案例。

Brand X Intelligence Radar 的产品目标，是把“看见信息”升级为“形成可执行情报”。

## 3. 产品定位

Brand X Intelligence Radar 是一套轻量级品牌情报雷达，面向可配置主品牌和样例竞品，持续生成中文优先的公开舆情视图。

它的核心定位包括：

- 情报优先：先呈现值得行动或复盘的焦点，而不是让用户从完整信息流里自行打捞。
- 证据优先：每个判断都尽量保留来源内容、作者信息、公开互动指标、原帖入口和相关上下文。
- 中文优先：默认提供中文译文或中文原帖，同时保留原文切换，降低跨语言阅读门槛。
- 可解释优先：评分、标签、风险等级和建议动作需要能被业务方理解，而不是只给出神秘分数。
- 归档优先：日报按日期沉淀，支持管理层回看、团队复盘和后续趋势对照。

当前产品最适合用作品牌海外公开舆情 MVP、管理层日会材料、市场/公关巡检台、竞品语境观察台和产品体验问题发现入口。

## 4. 用户与使用场景

### 4.1 目标用户

- 管理层：快速了解当日品牌风险、机会和竞品讨论背景。
- 公关团队：判断是否需要回应、准备口径或升级处理。
- 市场团队：识别可借势传播的正向体验、价格优势、活动反馈和用户表达。
- 客服与履约团队：发现退款、配送、售后、信任与安全相关的集中讨论。
- 产品与运营团队：观察用户自然表达中的体验问题、购买阻力和需求信号。

### 4.2 核心场景

- 晨会巡检：用“舆情焦点”查看今日最高优先级内容、风险级别和建议动作。
- 日报同步：用“舆情日报”把当日主品牌舆情、样例竞品基线和关键指标同步给相关团队。
- 原帖核查：从卡片进入原帖证据，查看作者、正文、互动指标、媒体和上下文。
- 历史复盘：按日期回看历史日报，判断某类问题是否重复出现或逐渐升温。
- 竞品对照：用样例竞品基线理解外部讨论热度和风险语境，而不是孤立解读主品牌声量。

## 5. 产品界面与信息架构

当前 MVP 包含四个主要页面。

### 5.1 舆情焦点

“舆情焦点”是产品第一屏，回答“今天最该看什么”。页面按传播风险、品牌相关度、业务价值和未来潜力筛出重点内容，并支持按风险、机会、观察、竞品等视角切换。

焦点卡片包含：

- 来源身份：作者、公开来源类型、粉丝量和发布时间。
- 中文正文：优先展示中文译文或中文原帖，支持切换原文。
- 分数与标签：展示 IPS 或 CSI、风险等级、情绪方向和命中标签。
- 公开指标：点赞、评论、转发、引用、浏览等公开传播信号。
- 入选原因：解释为什么该内容进入焦点，而不是只显示排序结果。
- 建议动作：例如持续监测、人工核查、公关准备回应、高层同步或传播机会。

### 5.2 全部舆情

“全部舆情”承接完整信息流，回答“今天还发生了什么”。它保留更多有效内容，适合扫描同一天的主品牌与竞品讨论，避免焦点页遗漏业务方关心但暂未达到高优先级的内容。

该页面强调日期、来源、正文、标签、分数和指标的快速浏览，适合运营、公关和产品团队做二次筛查。

### 5.3 舆情日报

“舆情日报”回答“如何对外或对上汇报今天的情况”。日报按日期归档，包含当日摘要、关键指标、主品牌焦点、样例竞品基线、历史列表和可复盘的原帖级材料。

日报页面适用于：

- 管理层每日查看。
- 团队例会同步。
- 风险事件后续复盘。
- 产品、客服、履约问题归类沉淀。

### 5.4 设置

“设置”不是传统意义上的系统配置页，而是公开可读的运行状态与方法说明页。它帮助用户理解数据是否完整、中文处理是否可用、质量漏斗是否正常，以及 IPS/CSI 分数如何计算。

设置页包含：

- 数据状态：样例模式或正常采集状态。
- 质量漏斗：原始采集、有效内容、主品牌/竞品候选与有效数量。
- 中文处理：译文覆盖、缺失与原文 fallback。
- 评分说明：IPS 与 CSI 的定义、维度和解释。
- 状态提示：采集受限、上下文未补齐、翻译缺失等非致命警告。

## 6. 核心能力

### 6.1 可配置品牌监测

产品围绕“主品牌 + 样例竞品”的结构工作。主品牌用于深度舆情识别和 IPS 排序，样例竞品用于形成轻量对照基线。

品牌配置包括：

- 品牌词、别名与多语言表达。
- 高风险词与机会词。
- 易混淆词及其上下文要求。
- 相关性上下文、垃圾内容和无关内容过滤规则。
- 每日采集规模与运行保护阈值。

这种配置化方式让产品可以从单一品牌 MVP 扩展到更多品牌或市场，但当前白皮书聚焦已实现的主品牌/样例竞品结构。

### 6.2 质量过滤与误匹配控制

产品不是简单按关键词收集内容，而是在归一化阶段判断内容是否真正相关。它会结合品牌词、上下文证据、风险/机会词、歧义词、垃圾词和无关词进行过滤。

例如，同一个英文词在购物售后语境和金融投资语境中可能含义不同。产品会通过上下文规则区分“退货/退款相关讨论”和“投资回报相关讨论”，避免把无关内容带入品牌舆情。

### 6.3 中文优先阅读

产品默认面向中文业务团队，因此对非中文公开内容进行中文处理。卡片优先展示中文译文，原文作为二级上下文保留。

中文处理遵循三条原则：

- 忠实：不改写事实，不替用户补充判断。
- 可回退：翻译缺失时展示原文，并在状态中提示。
- 可验证：保留原文入口，便于人工核查。

### 6.4 舆情聚类与主题归类

产品将有效主品牌内容聚合为舆情信号，并按主题进行归类。当前支持的主要主题包括：

- 履约与售后风险。
- 信任与安全风险。
- 监管、市场准入和公司背景。
- 正向体验与价格机会。
- 商品、优惠和库存信息。
- 竞品对照。
- 渠道、活动和合作动态。
- 一般观察。

主题归类的目标不是替代人工判断，而是帮助团队先把内容放入合适的业务语境。

### 6.5 证据链组织

产品围绕每个舆情信号组织证据链。证据类型包括：

- 热源：最早或最具代表性的起点内容。
- 热门：互动最高的相关内容。
- 最新：时间上最新的相关内容。
- 扩散源：高粉账号或引用较多的扩散节点。
- 当事人：疑似用户亲历或投诉表达。
- 支持/反证：当前 MVP 中保留结构，外部验证能力仍属于后续增强方向。

证据链设计的重点是让团队能从“系统判断”回到“原始证据”，降低误判和过度解读风险。

### 6.6 竞品基线

样例竞品模块用于建立外部讨论参照系。它统计竞品有效内容量、轻量情绪、代表性主题词和高互动帖子，用于判断主品牌当日舆情是否处在异常语境中。

竞品基线不用于替代完整竞品分析，也不用于自动得出市场结论。它的产品价值是让品牌团队避免孤立解读自身声量，在同一天的公开讨论环境里获得背景参照。

### 6.7 每日归档

产品按日期生成日报，并维护历史索引。每份日报都保留当日生成时间、窗口范围、关键指标、焦点内容和样例竞品基线。

日报归档的价值在于：

- 支持管理层回看。
- 支持问题复盘。
- 支持趋势观察。
- 支持团队形成统一口径。

## 7. 评分方法

产品使用两类分数：IPS 和 CSI。

### 7.1 IPS：Intelligence Priority Score

IPS 是主品牌舆情综合优先级分，范围为 0-100。它用于判断某条主品牌舆情是否应被优先关注。

当前 IPS 由七个维度加权形成：

| 维度 | 权重 | 含义 |
| --- | ---: | --- |
| 品牌相关度 | 20% | 内容是否明确指向主品牌、别名或多语言关键词 |
| 风险/机会强度 | 18% | 内容属于投诉风险、传播机会还是普通提及 |
| 当前影响力 | 16% | 互动量、浏览量、作者影响力等当前传播表现 |
| 未来发酵潜力 | 15% | 引用、账号影响力、相似内容密度和议题扩散空间 |
| 可信度 | 13% | 多帖佐证、上下文证据、高影响力账号和证据完整性 |
| 业务影响面 | 10% | 对支付、履约、售后、信任、安全等链路的影响 |
| 处置紧迫性 | 8% | 是否需要快速同步、核查或准备回应 |

在部分高敏议题中，如果未来发酵潜力明显较高，系统会叠加少量议题发酵加分。该加分用于体现履约、退款、配送等议题在公开社媒中可能快速聚集的业务风险。

### 7.2 风险等级

IPS 映射为四档风险等级：

| 等级 | 阈值 | 典型含义 |
| --- | ---: | --- |
| 紧急 | 88 及以上 | 需要高层同步或立即复盘 |
| 高风险 | 78-87 | 需要人工核查或公关准备 |
| 中风险 | 58-77 | 需要进入重点观察 |
| 低风险 | 0-57 | 常规监测或归档 |

风险等级不等于事实裁定。它是工作优先级，用于决定“先看什么、谁来看、是否升级”。

### 7.3 CSI：Competitor Signal Index

CSI 是样例竞品信号分，更偏观察价值。它用于判断竞品内容是否值得进入焦点页作为背景参照。

CSI 不与 IPS 直接比较，也不代表竞品风险严重程度。它的作用是辅助判断外部讨论热度和品牌语境。

### 7.4 建议动作

系统会基于主题、风险等级、可信度、当前影响力和未来潜力给出建议动作，例如：

- 高层同步。
- 管理层同步。
- 人工核查。
- 公关准备回应。
- 传播机会。
- 竞品对照观察。
- 渠道观察。
- 背景观察。
- 持续监测。

建议动作是辅助决策，不应替代人工事实核查和业务责任团队的最终判断。

## 8. 数据与系统流程

当前 MVP 的数据流程可以概括为：

```mermaid
flowchart LR
  A["公开社媒内容"] --> B["采集与运行保护"]
  B --> C["内容归一化"]
  C --> D["相关性与噪声过滤"]
  D --> E["中文处理"]
  E --> F["主题聚类"]
  F --> G["IPS/CSI 评分"]
  G --> H["证据链组织"]
  H --> I["日报与历史归档"]
  I --> J["静态舆情仪表盘"]
```

### 8.1 采集与运行保护

产品按每日窗口采集公开内容，并通过运行保护阈值控制单次任务规模。若触达保护阈值，系统会以部分结果生成日报，并在状态中提示谨慎解读声量变化。

### 8.2 归一化与过滤

采集后的内容被统一为稳定的数据结构，包括正文、作者、发布时间、公开互动指标、链接、媒体和品牌候选。随后根据品牌配置进行相关性判断和噪声过滤。

### 8.3 中文处理

非中文内容进入中文处理流程。若内容本身已为中文，则标记为中文原帖。若译文不可用，则保留原文并在状态中提示。

### 8.4 聚类、评分与证据链

有效主品牌内容被聚合成舆情信号，并计算 IPS。样例竞品内容形成轻量基线和 CSI。系统随后生成卡片、日报、历史索引和用于页面展示的数据包。

### 8.5 静态化交付

当前 MVP 面向低复杂度评审场景，采用静态仪表盘交付。该方式减少账号系统、后端服务和权限管理对 MVP 验证的干扰，让团队优先验证信息架构、数据质量、评分解释和日常工作流。

## 9. 产品可信度设计

### 9.1 透明状态

产品公开展示数据状态、原始采集量、有效内容量、主品牌与竞品拆分、中文处理覆盖和运行警告。用户不需要猜测“今天为什么内容少”或“这份日报是不是完整”。

### 9.2 证据可追溯

焦点卡片和详情视图保留原帖入口、作者信息、正文、公开指标、媒体和上下文。对于需要升级的内容，团队可以直接回到证据层核查。

### 9.3 判断与事实分离

产品区分三类信息：

- 原始事实：公开正文、作者、时间、互动指标和链接。
- 系统加工：中文译文、摘要、主题、标签、聚类和分数。
- 行动建议：核查、回应、同步、观察或借势传播。

这种分层可以减少“系统总结被误当作事实”的风险。

### 9.4 样例与真实状态区分

当产品处于样例数据模式时，页面会明确提示样例内容用于验证结构和交互，不代表真实舆情，且样例原帖入口不会跳转至外部站点。

### 9.5 安全与脱敏

公开产物不应暴露非公开品牌配置、凭证、私有日志、本地缓存或其他运行细节。当前产品在公开输出阶段对敏感字段和内部命名做了清理，并提供基础安全扫描以降低误提交风险。

## 10. 适用边界

Brand X Intelligence Radar 是公开舆情情报 MVP，而不是全量社媒监听系统、法律合规裁决系统或自动化危机处置系统。

当前边界包括：

- 数据覆盖边界：产品只覆盖已配置来源和采集窗口内的公开内容，不代表全网完整声量。
- 语义判断边界：主题、情绪、风险等级和建议动作是辅助判断，关键事件仍需人工核查。
- 翻译边界：中文译文用于提升阅读效率，重要表达应结合原文确认。
- 竞品边界：样例竞品基线用于背景参照，不构成完整竞品研究。
- 实时性边界：当前以日报和归档为核心，不承诺秒级实时预警。
- 外部验证边界：支持/反证结构已预留，但完整外部事实核验能力仍需后续增强。

明确边界不是削弱产品价值，而是防止团队把 MVP 用到不适合的决策场景中。

## 11. 衡量指标

产品是否有效，不应只看采集数量，而应看它是否提升了团队判断效率和复盘质量。

建议关注以下指标：

| 指标 | 含义 |
| --- | --- |
| 有效内容率 | 有效内容 / 原始采集内容，衡量过滤质量 |
| 焦点命中率 | 焦点内容中被业务方认可为值得关注的比例 |
| 误报率 | 被人工判断为无关、误匹配或不应进入汇报的比例 |
| 中文可读率 | 可直接中文阅读的内容占比 |
| 核查闭环率 | 高风险内容中完成原帖核查和责任团队判断的比例 |
| 日报使用率 | 管理层或业务团队实际打开、引用、转发日报的频率 |
| 历史复盘引用量 | 历史日报被用于复盘、会议或策略讨论的次数 |

MVP 阶段最关键的不是追求内容越多越好，而是提高“少量关键内容被及时、正确、可追溯地看见”的概率。

## 12. 路线图

### 12.1 近期增强

- 提升来源卡片一致性和媒体展示质量。
- 优化中文译文、原文切换和长文本阅读体验。
- 增强质量漏斗解释，让非技术用户更容易理解数据状态。
- 优化焦点入选原因，减少泛化表达，提升业务可读性。
- 增强详情页证据链展示，让热源、扩散源、当事人和最新内容更易扫描。

### 12.2 中期增强

- 引入更稳定的延迟发酵跟踪模块，观察舆情跨日升温或降温。
- 丰富外部支持/反证验证能力，降低未证实传播的误判风险。
- 支持更多可配置市场、语言和品牌线。
- 增加团队标注闭环，把人工判断反哺评分和过滤策略。
- 建立风险处置工作流，如任务状态、责任人、处理结果和复盘备注。

### 12.3 长期方向

- 从“日报型雷达”演进为“品牌情报操作台”。
- 从“单品牌 + 样例竞品”扩展到多品牌、多市场、多渠道情报网络。
- 从“系统建议动作”演进到“团队协同闭环”，覆盖发现、核查、响应、沉淀和策略复盘。
- 从“规则与轻量评分”逐步升级为可评估、可校准、可审计的智能情报判断体系。

## 13. 结语

Brand X Intelligence Radar 的核心价值，不是把公开社媒内容简单搬到一个看板里，而是把品牌团队每天面对的嘈杂信息转化为有优先级、有证据、有中文语境、有历史归档的情报资产。

在 MVP 阶段，产品应继续坚持三条原则：

- 先保证核心链路稳定，再扩展更多能力。
- 先保证判断可解释，再追求更复杂的智能分析。
- 先保证公开输出脱敏、安全、可信，再扩大分享范围。

当团队能够每天稳定回答“今天最重要的品牌舆情是什么、为什么重要、证据在哪里、下一步谁来处理”时，这个产品就已经从监测工具进入了品牌管理基础设施的范畴。
